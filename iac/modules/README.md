# Shared OpenTofu modules

Shared modules under `iac/modules/` — `ingress`, `temporal`, `grafana-dashboard` — that are
consumed by the service root modules in this repo and (optionally) from other repos.

## Consuming from another repo

Point `source` at the module subdirectory over git and pin to a **full commit SHA**:

```hcl
module "ingress" {
  source = "git::https://github.com/jdc-projects/homelab.git//iac/modules/ingress?ref=<commit-sha>"
  # ...
}
```

- `git::` prefix and the `//iac/modules/<name>` subdirectory path are required.
- Pin to a full commit SHA for reproducibility. There are no moving or CalVer tags, and
  `?ref=main` is discouraged (non-reproducible `tofu init`).
- OpenTofu clones into `.terraform/` on `tofu init` — the homelab source never appears in
  the consumer's working tree.

## Cluster coupling (read before consuming)

These modules are built for and **coupled to this homelab cluster**. They are not portable
to an arbitrary Kubernetes cluster without modification. Consumers must target the same
cluster (or accept the coupling notes below). Specifically, they assume:

- The homelab's kubernetes backend state in namespace `tf-state` (secrets
  `tfstate-default-<module>`), reachable via the same kubeconfig the homelab root modules
  use.
- The homelab's installed operators and CRDs: traefik (with the traefik-oidc-auth and
  api-key-auth plugins), cert-manager, CloudNativePG, grafana-operator, prometheus-operator.
- The homelab's specific middleware names (`cloudflare`, `geoblock`, `crowdsec-bouncer`,
  …), storage classes (`openebs-zfs-localpv-random`), and Grafana instance label
  (`dashboards = "grafana"`).

Per-module coupling notes are in each section below.

## `ingress`

Provisions a Traefik `IngressRoute` (plus a `Service` if needed) for an application, wired
to the homelab's shared middleware chain (Cloudflare IP restore, geoblock, CrowdSec
bouncer) and optional authentication: none, interactive OIDC (full login flow via the
traefik-oidc-auth plugin), API OIDC (bearer-token offload), or static API key.

### Coupling notes

- Reads remote state from the homelab: `data "terraform_remote_state" "traefik"` (for the
  traefik namespace and shared middleware) and `"keycloak"` (for realm IDs and the
  Keycloak URL when in a managed OIDC mode).
- Reads remote state via `config_path = var.kubeconfig_path` (default `"../cluster.yml"`,
  resolved relative to the directory tofu runs in). External consumers override
  `kubeconfig_path` with their own kubeconfig location; in-repo callers use the default
  (the homelab kubeconfig at `iac/cluster.yml`, generated by
  `iac/cluster-config-write.sh`).
- Requires the `keycloak` provider to be configured (the homelab configures it via root
  module provider blocks; external consumers must do the same).

### Snippet

```hcl
module "whoami_ingress" {
  source = "git::https://github.com/jdc-projects/homelab.git//iac/modules/ingress?ref=<commit-sha>"

  name         = "whoami"
  namespace    = "whoami"
  domain       = "whoami.example.com"
  target_port  = 80
  selector     = { app = "whoami" }

  auth_mode           = "oidc-interactive"
  keycloak_auth_realm = "primary"
}
```

### Key variables

Required: `name`, `namespace`, `domain`, `target_port`, and exactly one of
`selector` / `external_name` / `existing_service_name` (+ `existing_service_namespace`
when using an existing service).

Notable optional: `auth_mode` (`none` | `oidc-interactive` | `oidc-api` | `api-key`),
`keycloak_auth_realm`, `auth_oidc_provider` (bring-your-own IdP, skips Keycloak client
provisioning), `do_enable_cloudflare_middleware` / `do_enable_geoblock` /
`do_enable_crowdsec_bouncer*`, `extra_middlewares`, `kubeconfig_path` (override the
kubeconfig used to read remote state; default `"../cluster.yml"`).

Full reference: [`ingress/variables.tf`](ingress/variables.tf).

### Outputs

`api_key` (sensitive; set only when `auth_mode = "api-key"`),
`auth_interactive_middleware_name` / `_namespace` (for sharing a session cookie across
ingresses on the same host), `auth_api_middleware_name` / `_namespace`.

Full reference: [`ingress/outputs.tf`](ingress/outputs.tf).

## `temporal`

Deploys a Temporal cluster (server + UI + a CloudNativePG Postgres database) into a
namespace. Optionally exposes the UI via the `ingress` module.

### Coupling notes

- Uses CloudNativePG with hardcoded storage class `openebs-zfs-localpv-random` and snapshot
  class `openebs-zfs-localpv` — homelab-specific.
- `enablePodMonitor = true` on the DB assumes the prometheus-operator CRD is installed.
- The optional UI ingress is built by the `ingress` module (see its coupling notes). By
  default the temporal module sources `ingress` from this repo's `main` branch; in-repo
  callers override `ingress_module_source = "../ingress"` to use the local copy.

### Snippet

```hcl
module "temporal" {
  source = "git::https://github.com/jdc-projects/homelab.git//iac/modules/temporal?ref=<commit-sha>"

  namespace   = "temporal"
  ui_domain   = "temporal.example.com"
  cors_origins = "https://app.example.com"
  es_host     = "opensearch" # null = SQL-only visibility
}
```

### Key variables

Required: `namespace`. Notable optional: `name_prefix`, `db_instances`,
`is_db_hibernate`, `es_host` (null = SQL visibility; set for OpenSearch advanced
visibility), `server_image` / `ui_image` / `db_image`, `ui_domain` (null = UI not
exposed), `cors_origins`, `ingress_module_source` (override the UI ingress submodule
source), `kubeconfig_path` (forwarded to the ingress submodule; default `"../cluster.yml"`).

Full reference: [`temporal/variables.tf`](temporal/variables.tf).

### Outputs

`service_host` (`<name_prefix>:7233` — gRPC address for workers), `db_cluster_name` (the
CNPG cluster name).

Full reference: [`temporal/outputs.tf`](temporal/outputs.tf).

## `grafana-dashboard`

Creates `GrafanaDashboard` CRs (one per entry) for grafana-operator, targeting the
homelab's Grafana instance by label.

### Coupling notes

- Hardcodes the instance selector `{ dashboards = "grafana" }` — the homelab's Grafana CR
  label. A consumer targeting a differently-labelled Grafana would need to fork or this
  label would need promoting to a variable.
- Dashboards land in a folder named after `var.namespace` (grafana-operator v5 behaviour).

### Snippet

```hcl
module "dashboards" {
  source = "git::https://github.com/jdc-projects/homelab.git//iac/modules/grafana-dashboard?ref=<commit-sha>"

  namespace  = "prometheus"
  dashboards = {
    overview = file("${path.module}/dashboards/overview.json")
  }
}
```

### Variables

Required: `namespace`, `dashboards` (map of name -> dashboard JSON string).

Full reference: [`grafana-dashboard/variables.tf`](grafana-dashboard/variables.tf).
